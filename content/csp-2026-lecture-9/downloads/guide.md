## 一、这场讲座解决什么问题

竞赛失利有两类原因：一类是算法不会，另一类是**会做但没交上去、或交错了**。张康开场就把重点放在第二类：

> 历年都有选手因操作不规范或突发状况处理不当，导致真实水平未能如实反映在测评结果中。

整场讲座只讲考场实操：程序回收系统怎么用、机器卡死怎么办、编译为什么过不了。技术细节都不难，难在**考场上没时间现场摸索**。

## 二、程序回收系统：七个步骤

先纠正一个最常见的误解：

> **程序回收系统不是评测系统，它不编译代码。** 代码有编译错误它不会提醒你，它的作用只是把你的代码文本收集上来。

所以「本地能跑」和「回收系统里有正确版本」是两件必须分别确认的事。

### 步骤 1　打开网站并登录

- 网址是**各考场自己的 IP**（如 `192.168.1.12`），开考前进场时看黑板板书。
- 用户名是准考证号，密码来自考场发的**密码条**（与准考证对应）。
- 登录后先等试题下发，其间可以核对**个人信息**是否正确。

### 步骤 2　读考场须知

登录后侧栏有「考场须知」，等同纸质考试要求。**开考前逐条读一遍**，发现自己有不合规的地方还来得及改。

### 步骤 3　下载试题、找到文件、解压

- 监考员下达开考指令后，试题才能下载。
- 文件默认在**主目录下的「下载」（Downloads）目录**。这是 Linux 新手最容易卡住的一步——浏览器下载完就不管了，回头找不到文件。
- 压缩包**有密码**，开考前 2–3 分钟由监考员给出（板书或通过回收系统发消息）。解压后的 PDF 题面**可能还有一层密码**。

### 步骤 4　写代码并提交

- 左侧点「答题」，右侧出现各题的提交按钮；点某题弹出提交框，把代码粘贴进去。
- **提交前自己检查编译**（系统不会替你查）。
- 提交成功会弹提示「程序已提交，建议认真检查」，这不是走过场，是提醒你**确认交的是哪一版**。

### 步骤 5　查看提交状态与核对源码

- 列表显示每题的**已提交 / 最后提交时间 / 代码长度**。
- 点「查看」能看到**最后一次提交的源码**——用来确认「这就是我想交的那份」。
- 步骤 5 在课件里拆成两组：一组讲状态与源码核对，一组是界面截图对照。

### 步骤 6　查看未读消息与考场通知

- 消息一般是**题目订正**或与比赛环境相关的通知。
- 不必一直盯着，监考员会提醒；提交题目时若侧栏有未读数，点进去看即可。

### 步骤 7（收尾）　按清单做最后检查

考试结束前 **15 分钟和 5 分钟**监考员都会提醒。张康的建议很直接：

> 最后 5 分钟已经很难再改代码了，不如把已提交的题目逐个核对一遍。

**必须形成的一个观念**：

> 你保存在自己编辑器里、自己电脑上的代码都不算数，**只有提交到回收系统里的那一份才是你真正的答卷。**

## 三、考场常见问题（与编程无关的那一类）

### 1. 违规携带物品：没有作弊意图也算违纪

最常见的情形不是作弊，而是习惯：开考后书包、手机还在座位上。手机响了或被监考员发现，按考试要求即构成违纪，**当場考试可被记零**。

> 建议：开考前把物品按考场要求放好，电子设备该关机的关机。

### 2. 画面还在，鼠标键盘全无响应

最常见成因是**自己写的程序申请了过多内存**，把整台机器拖死。少数情况是机器连续工作三四小时后自身卡住。

处理要点：

- **先举手报告**，不要自己重启。考场是虚拟机环境，自己重启后可能回不到考试系统。
- 重启后**磁盘上的代码还在**，平时多按 Ctrl+S 就不会丢太多；做一题提交一题，损失更小。
- 若确属系统原因且耽误较久，可申请**补时**（以监考员现场判断为准）。
- 恢复后**先看代码再运行**：内存分配、死循环、无限递归，这三类先排查，否则再一次卡死，心态会崩。

### 3. 机器或网络故障

一个考场几百上千台机器连续工作几小时，偶发故障难免。真正影响考试的往往不是故障本身，而是**选手在等待时的急躁**。

- 举手报告，让监考员**记录故障起止时间**。
- 等待重启的那一两分钟，**继续在草稿纸上推演**，不要中断思路；也可以趁间隙去洗手间、打水（需监考员同意）。
- 恢复后**检查文件**：没保存的那几行确实会丢，有人以为还在，其实已经没了。

### 4. 换机后无法登录

换机后监考员需要**同步修改准考证号绑定的 IP**，这中间有时间差。等监考员通知后再登录，座位不能随意更换。

> 这也是「做一题提交一题」的理由：换机后旧机器上的代码大概率拿不过来，而回收系统在服务器上。

## 四、NOI Linux 实操：十一类常见问题

这一段是全场最实用的部分，张康用 NOI Linux 实机演示了每一个故障。课件把它们归为五类，实际讲到了十一项：

### 1. 打开 `.in` / `.answer` 大文件导致死机

去年 CSP 某题的数据包里有 17.8 MB 的输入文件（约 1700 万个数），用文本编辑器打开，滚动条直接忙不过来，性能差一点的机器**当场卡死**。

- 打开前先看「大小」列。
- 想看数据：用自己写的程序读前若干行输出，或用终端 `head` / `tail`。
- 人眼看完整份输入没有意义，也没那个时间。

### 2. 程序没有响应

一般是自己的程序死循环或无限递归。可以直接关掉，不必紧张。

### 3. 机器卡死

见上一节第 2 条。**注意归因**：如果是自己程序导致的，相应后果也要自己承担。

### 4. 运行时报「段错误（核心已转储）」

等价于评测网站上的「运行错误」。常见原因：数组下标越界、指针写错、栈里放的东西太多、无限递归。

### 5. 无法编译（四种常见原因）

| 原因 | 表现 | 处理 |
|---|---|---|
| **保存在中文目录** | Code::Blocks 存到「桌面」等中文路径，之后无法编译 | 养成习惯：**不要在中文目录下写代码** |
| **数组开得太大** | 如 `const int N = 1e9 + 5;`，链接阶段报 `.bss` 段 / PC32 against `.bss` | 全局数组超过限制会**连编译都过不了**，不是机器坏 |
| **同名目录冲突** | `hello.cpp` 生成可执行文件 `hello`，而目录下已有 `hello/` 文件夹 | 改名或删掉同名目录，较少见 |
| **程序还在运行** | 上一次运行的黑窗口没关，重新编译覆盖不了可执行文件 | 关掉多余运行窗口再编译 |

第二种在考场上最容易误判成「机器有问题」，去年就有不少同学因此举手。

### 6. 不要改分辨率

机房显示器能承载的输出分辨率有限，改大或改错可能导致整个系统显示不出来。修得回来，但**代价是大量时间，而且算你自己的操作**。

> 觉得字不舒服，用 Ctrl + 滚轮调字体（Code::Blocks 等编辑器都支持），比改分辨率安全得多。

### 7. Insert 键导致「覆盖模式」

光标变成方块/黑色竖线，新输入的字符把后面的字吃掉。按一下 `Insert`（键盘上常标 `Ins`）即可恢复。自己观察就能解决，不必举手等监考员。

### 8. 数字小键盘用不了

`NumLock` 没开，或键盘上根本没有这个键。写代码主要用主键盘区那排数字，影响不大。

### 9. 找不到程序的输入文件

题目要求读 `road.in`，而给你的是 `road1.in`、`road2.in` 样例；更常见的是 **`.in` 文件和可执行文件不在同一目录**——程序只在当前目录找。

> 处理：把输入文件复制（或移动）到可执行文件所在目录，再运行。

### 10. 下载的题目样例在哪

主目录 → 「下载」（Downloads）。和第 3 步同一件事，但考场上问得最多。

### 11. Code::Blocks 工具栏消失了

误点了菜单，把工具栏切到 `minimal` 布局，看起来「什么都没有了」，其实代码还在。

> 恢复：`View → Perspectives → Default`，弹出「是否保存」时选 **No**。常用按钮和快捷键会全部回来。

## 五、其他建议：把熟悉环境当成复习的一部分

### 1. 尽量用官方系统训练

NOI Linux 在**官网**可以下载。用官方环境训练，本身就是在练考场操作。

### 2. 装不上？让 AI 帮你装

张康的立场很务实：写过一段时间代码之后，装个虚拟机不该是难事，**敢试就行**。而今年更省事的办法是让 AI 带你装：

- 先把自己的情况说清楚：参加哪一轮、J 还是 S、操作系统是什么、处理器型号和内存大小（不知道就直接问 AI「我的操作系统是什么」）。
- 装的过程中出错，**截图或拍照发给 AI**，比文字描述有效。
- 现在带 Agent 能力的工具（他举例提到豆包、WorkBuddy 一类）可以直接操作你的电脑，帮你完成部分安装步骤。
- 装完后按讲座演示的流程走一遍：打开网站、写代码、做几道题。

### 3. 赛前线上程序回收测试

主办方提供赛前线上测试（**今年安排在下周四 [待核对]**）。建议完整走一遍：登录 → 下载 → 解压 → 提交 → 查看。

> 在测试里把不熟练的地方暴露出来，赛场上就不会碰到「奇怪的问题」。

### 4. 心态：把注意力放在还能做的事上

- 上午 J 组 3.5 小时、下午 S 组 4 小时，一两分钟的意外和去趟洗手间差不多。
- 真正的问题及时报告；确属系统原因耽误的时间，监考老师和主办方**会保证公平、把时间补回来**。
- 机器重启时，脑子里的题继续想，代码继续设计——**连续性并没有被打断**。

## 六、现场问答

**Q1：第一次参赛，平时在 Windows 下编程，最后几天该继续刷题还是熟悉系统？**

熟悉系统。多刷几道题当然有训练价值，但对从没用过 NOI Linux 的同学，**熟悉系统带来的收益更大**——它直接决定你在考场上的操作是否流畅。他打的比方：换了新球拍，赛前几天总得先适应这块拍子。

**Q2：有哪些往年选手常犯、但可以提前避免的失误？**

- **样例一定要全测**，尤其是大样例；但样例覆盖不到所有情况，所以还要自己构造边界：题目说 n 从 1 到 100 万，那 1 和 100 万都要试。
- **初始化遗漏**：某个变量本该置 0 却没写，本地测试恰好没暴露（编辑器或系统可能给了个「碰巧正确」的默认值），这种只能靠习惯和复查。
- **最后时刻还在大改代码**：改完没时间重测，可能只对了一个点、其余全错，而你自己不知道。
- 网上盛传的极端意外，多数是「认真测过就能避免」的问题。

**Q3：`freopen` 要不要写？**

**看题目。** 真题第一页的表格会写明是「标准输入」还是「文件输入」。写了「文件输入」就必须 `freopen`，让程序从文件读数据。题目一定会说明输入方式，否则没法评测。

**Q4：（主持人的补充提示）**

> 程序回收系统**仅针对北京市选手**，外地选手请按本省要求提交代码。

## 七、可直接执行的清单

**赛前一周**

- [ ] 装好 NOI Linux（装不上就让 AI 带你装）
- [ ] 在 NOI Linux 里完整走一遍：打开浏览器 → 登录回收系统 → 下载 → 解压 → 提交 → 查看源码
- [ ] 参加赛前线上程序回收测试（下周四 [待核对]）
- [ ] 把「新建代码文件不要放中文目录」变成肌肉记忆
- [ ] 记住常用操作：`Ctrl+S` 保存、`Ctrl+滚轮` 调字号、`Insert` 切换覆盖模式

**进场到开考前**

- [ ] 看黑板上的考场 IP
- [ ] 手机、书包按考场要求放置，电子设备关机
- [ ] 用准考证号和密码条登录，核对个人信息
- [ ] 逐条读完「考场须知」

**开考后**

- [ ] 下载试题 → 主目录「下载」找文件 → 用密码解压 → 打开 PDF（可能还有密码）
- [ ] 写好一题就提交一题（换机、卡死时的唯一保险）
- [ ] 提交前自己确认能编译
- [ ] 大文件不直接打开，用程序或 `head` 看前几行

**结束前 15 分钟 / 5 分钟**

- [ ] 逐题核对「查看」里的源码是不是要交的那版
- [ ] 看侧栏有没有未读消息
- [ ] 停止改动，不再大改代码
