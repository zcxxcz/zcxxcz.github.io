快速跳转

一、重复计算同一个子问题 J S

暴力做法：用递归或搜索把所有可能都算一遍。问题是——同一个子问题的答案被反复算了无数次，算完就忘，下次遇到又重新推一遍。

瓶颈：不同状态的总数其实很少（通常只有 n 个或 n×V 个），但被访问的次数是指数级的。差别就在“算过的东西有没有记下来”。
优化方向：记忆化搜索 / 动态规划——用一张表把算过的答案存起来，下次直接查表。
  • 核心公式：时间 ≈ 状态数 × 每个状态的转移代价。这是估 DP 复杂度的万能公式。
  • 能量守恒：暴力之所以慢，是因为它连“已经算过的”都不肯存下来，只用时间硬扛。

计数方式：按递推公式计算真实递归调用次数（与跑一遍递归得到的数字一致），所以 n 大到 35 也不会卡。
适用边界：记忆化只在“状态数量有限且会重复出现”时有用。如果每个状态只出现一次（比如纯枚举所有排列），记下来也没人来查，白费空间。

1.2 0/1 背包：枚举 2ⁿ 种选法 vs 填一张表

n 件物品，每件有重量和价值，背包容量 V。暴力思路：每件物品“选或不选”，一共 2⁸ 种组合，每种都试一遍算总重和总价值。

DP 表长什么样（行 = 物品，列 = 容量）

表格里第 i 行第 j 列表示“只考虑前 i 件物品、容量为 j 时能拿到的最大价值”。每个格子只被算一次，填表顺序从左到右、从上到下——这就是把 2ⁿ 次尝试压成 n×V 个格子的过程。
边界：n×V 太大的时候 DP 会爆内存/超时（比如 V = 10⁹）。这时要换思路：值域小数量少时可以“以价值为下标”做 DP，或者用折半搜索（见 7.3）。

1.3 DP 自己也会有第二层瓶颈

写出 DP 只是第一步。转移式写出来以后，还要看转移本身贵不贵：

转移长这样优化手段去哪看演示
从前面一段区间里取最大/最小值
dp[i]=max(dp[j..i-1])+a[i]		单调队列：O(n²) → O(n)

记这句话：“DP 的状态数决定下限，转移写法决定上限。” 先数状态，再优化转移。

二、反复求区间和或区间信息 J S

暴力做法：每来一次询问，就从 l 循环加到 r。一次询问最多扫 n 个数，q 次询问就是 O(nq)——n 和 q 都是 10⁵ 的话，10¹⁰ 次运算，超时。

瓶颈：相邻两次询问的区间高度重叠，中间那段被重复加了无数遍。同样的加法做了无数次。
优化方向：先花 O(n) 预处理，把“区间和”变成“两个前缀值相减”。不修改 → 前缀和；要修改 → 树状数组 / 线段树。
场景算法难度复杂度
静态区间和（只查不改）前缀和J预处理 O(n)，每次查询 O(1)
多次区间加，最后才查询差分J每次修改 O(1)，最后还原 O(n)
二维矩阵区间和二维前缀和J查询 O(1)
静态区间最值（RMQ）ST 表S预处理 O(n log n)，查询 O(1)
单点修改 + 区间求和树状数组S修改/查询都 O(log n)
区间修改 + 区间查询线段树（懒标记）S都 O(log n)
修改很难用线段树维护（比如区间众数）分块S每次 O(√n)
判断口诀：不修改 → 前缀和 / ST 表；有修改但操作简单 → 树状数组；操作复杂（区间加、区间乘、区间最值混着来）→ 线段树；线段树也维护不了 → 分块。

2.1 前缀和：O(length) 的扫描变成 1 次减法

数组里的值固定不变（示意数据：12 个数，范围 1〜9）。拖动 l、r 选择询问区间。

原数组 a（0 号下标开始）

前缀和数组 P（P[k] = a[0]+…+a[k-1]，长度为 n+1）

为什么成立：P[r+1] 表示“从 0 加到 r 的和”，P[l] 表示“从 0 加到 l−1 的和”。两者相减，前面重复的部分刚好抵消，剩下 a[l..r]。
代价：预处理一次性花 n 次加法；之后每次询问只花 1 次减法。
适用边界：前缀和只适合“元素不会变”的场景。如果数组会被修改，改一个数就得重新算一遍后面所有前缀和（O(n)），这时候要用树状数组（见 2.3）。

2.2 差分：把“区间加”变成两个点上的修改

问题：给一个长度 12 的数组，做 5 次“区间 [l, r] 全部加 v”的操作，最后输出整个数组。拖动看前 k 次操作执行后的效果。

差分数组 d（只标出被改动的两个位置）

还原后的原数组 a（对 d 做一次前缀和得到）

为什么成立：给区间 [l, r] 每个数 +v，等价于在差分数组上做两件事：d[l]+=v 和 d[r+1]−=v。做前缀和时，从 l 开始 v 生效，到 r+1 被减掉，正好只在区间内生效。
所以每次区间修改只要 O(1) 两笔操作，改 k 次就是 O(k)，最后 O(n) 还原一次。
适用边界：差分适合“先连续修改、最后一次性查询”的场景。如果改一次就要问一次，得用树状数组/线段树。
注意：d 数组要多开一位（r+1 可能等于 n）。

2.3 树状数组：能改又能查，每次只要 log n

树状数组（BIT）用 lowbit(i) = i & (−i) 把数组分成一层一层的“区间块”。拖动选择修改位置和查询前缀，看它只动了哪几个格子。

原数组 f（1 号下标开始，只显示累加次数）

树状数组树 c（蓝色 = 修改时经过的格子，青色 = 查询时经过的格子）

n 变大时，log n 和 n 的差距

两条路径：
修改 p：i=p; while(i<=n){ c[i]+=v; i += lowbit(i); } → 向上不断“变大”
查询 q：i=q; while(i>0){ s += c[i]; i −= lowbit(i); } → 向下不断“变小”
两条路径的长度都不超过 log₂n+1。所以 n=10⁶ 时，每次操作只要 20 次左右，而暴力重算是 10⁶ 次。
适用边界：树状数组的“区间和查询”要利用前缀和相减，所以要求运算可差分（加法、异或可以；最大值不行）。区间最值请用线状数组/线段树/ST 表。区间修改 + 区间查询需要“差分 + 双树状数组”或干脆线段树。

2.4 ST 表：静态区间最值，查一次只要 1 次比较

问题：数组不变，反复问“区间 [l, r] 的最小值是多少”。暴力要扫 length 个元素。

原数组 a（16 个数）

稀疏表 st[k][i] = 从 i 开始、长度 2ᵏ 这一段的最小值

为什么只要 1 次比较：设区间长度 len = r−l+1，取 k = ⌊log₂len⌋。用两个长度都是 2ᵏ 的块盖住这个区间：左边一块从 l 开始，右边一块从 r−2ᵏ+1 开始。
因为 2ᵏ ≤ len < 2ᵏ⁺¹，两块必然有重叠且能完整覆盖——重叠不影响求最小值（最小值重复取最小还是最小值）。所以答案 = min(st[k][l], st[k][r−2ᵏ+1])。
适用边界：①ST 表不支持修改，改一个数就要整表重建；②上面的“两块覆盖”技巧只对可重复贡献的运算成立（min/max/gcd/按位与或都可以），区间和不行（重叠部分会被算两次）。区间和请用前缀和。

三、反复找最值或动态维护有序集合 J S

暴力做法：每要一次最大值/最小值，就把整个区间或整个数组扫一遍，O(n)。如果是“动态”的（会插入、删除），每次操作都 O(n)。

瓶颈：上一次扫描时看到的信息全都丢掉了，下一次又从零开始比。重复比较是浪费的根源。
优化方向：用能“记住相对大小关系”的结构——堆（动态取最值）、单调队列/单调栈（滑动窗口或找前/后第一个更大更小）、set/map（动态前驱后继）。
工具解决什么每次代价难度
堆 / 优先队列动态集合里反复取最大/最小O(log n)JS
单调队列滑动窗口内的最值每个元素进出一次，均摊 O(1)S
单调栈每个数左/右第一个更大（更小）的数均摊 O(1)S
set / multiset / map动态插入删除 + 查前驱后继O(log n)JS

3.1 单调队列：滑动窗口最大值，每个数只进出一次

问题：长度为 n 的数组，每个长度为 k 的窗口的最大值分别是多少？窗口从左往右滑 n−k+1 次。

队列里存的是下标，不是数值。队列中下标对应的值从队首到队尾单调递减，所以队首永远是当前窗口的最大值。
入队前先把“比我小又比我老”的统统弹掉——它们以后再也不可能成为最大值了，留着只是白占位置。这就是“每个元素最多进队一次、出队一次”的原因，均摊 O(1)。
适用边界：①窗口要同时满足“从左往右滑、只增不减”的推进方式；②求最小值就把比较方向反过来（维护递增队列）；③队列里必须存下标，否则没法判断元素是否已经滑出窗口。

3.2 单调栈：每个数右边第一个比它大的数

暴力：对每个位置 i，往右找第一个 a[j] > a[i]，最坏 O(n²)。单调栈一遍扫完，O(n)。

（示意数据：10 个数，范围 1〜13）
核心动作：依次把每个下标压栈；压栈前，只要“栈顶的值 < 当前的值”，就说明当前这个数就是栈顶右边第一个更大的数 —— 把栈顶弹出并记录答案。
因为每个下标恰好进栈一次、出栈一次，总操作次数 ≤ 2n。
适用边界：①“严格更大”用 < 弹栈，“大于等于也算更大”要用 <=，这里不一样答案就不一样，读题要仔细；②循环数组（环形）可以把数组复制一遍接在后面；③柱状图最大矩形、接雨水都是这个模板。

3.3 堆：合并果子（每次取最小的两堆合并）

问题：n 堆果子，每次把两堆合并成一堆，消耗 = 两堆之和。求合并成一堆的最小总消耗。
结论：每次取最小的两堆合并，总消耗最小。难点在于“每次都要知道现在最小的两堆是谁”。

堆做法：每一轮合并（自动逐步演示）

为什么堆快：暴力每轮都要“线性扫描找两个最小”，每轮约 2k−3 次比较，n 轮累计 ~n² 次。
堆把“数组”变成“完全二叉树”，最小元素永远在根。每次取出/放入只需沿着树的一条路径比较 log n 次，n 轮总共 ~n log n 次。
适用边界：①单纯求“最小的 k 个数”不需要堆，排序一遍更好；堆的优势在动态（边插入边取最值）；②要取最大就用大根堆（把值取相反数也可以）；③C++ 的 priority_queue 默认是大根堆，要小根堆得写 greater<int>；④堆只能取堆顶，取中间某个元素是 O(n)。

3.4 顺带一提：Dijkstra（最短路）也用堆

Dijkstra 每次要“在所有还没确定的点里，选距离最小的那个”。这正是堆最擅长的事，所以堆优化 Dijkstra 的复杂度是 O((n+m) log n) —— 第 8 节有完整的逐步演示。

看到“每次都要取出当前最小的”这种描述，第一反应就应该是：堆。

四、反复查找某个值是否存在 J S

暴力做法：每问一次“这个值在不在里面”，就把数组从头到尾看一遍，O(n)。q 次询问就是 O(nq)。

瓶颈：每一次查找都没有利用“前面已经查过”的信息，也没有利用数据的任何结构（有序性、值域大小、重复度）。
优化方向：先对数据做一次整理，让以后的每次查找变便宜——排序（为了二分）、哈希（为了 O(1) 命中）、桶（值域小的时候直接下标访问）、离散化（值域大但数量少的时候先压缩值域）。
方法适合什么数据查找代价代价 / 坑
排序 + 二分数据静态、有序性可复用O(log n)排序 O(n log n)；插入新元素代价高
哈希表 / unordered_map只关心“有没有、有几个”平均 O(1)最坏 O(n)；需要额外空间；不支持“找前驱后继”
map / set（红黑树）要动态有序、要前驱后继O(log n)常数比哈希大
桶（计数数组）值域很小（比如 ≤10⁶）O(1)值域一大就开不下数组
离散化值域很大（10⁹）但只有 n 个数配合桶/树状数组用需要先排序去重，本质是“把值换成排名”

4.1 排序 + 二分：16 个数最多问 4 次

数组已经从小到大排好（16 个不重复的数）。拖动选择要查找的值，看二分是怎么一步步把范围砍半的。

为什么是 log：每次比较之后，可能的范围只剩一半。16 → 8 → 4 → 2 → 1，4 次就够了。这就是 log₂16 = 4。
n = 10⁶ 时 log₂n ≈ 20，也就是最多问 20 次；线性扫描最坏要问 10⁶ 次。
适用边界：①二分查找必须有序！②如果要反复插入/删除元素，维护有序数组的代价很高（一次插入 O(n)），这时应该用 set / map（O(log n)）；③二分查找有很多易错点：mid = lo + (hi−lo)/2 防溢出、边界要不要取等、找不到时返回什么。建议固定一套自己写熟的模板。

4.2 两数之和：为什么哈希能把 n² 变 n

问题：数组里找一对数，使它们的和等于 target。暴力：枚举所有点对，n(n−1)/2 次比较。

哈希的思路（一句话）：从左往右扫，对每个数 a[i]，与其每次回头找“有没有一个数等于 target−a[i]”，不如一边扫一边把见过的数记到哈希表里，然后直接问“target−a[i] 见过吗”。查表是 O(1)，所以总共 O(n)。
注意顺序：先查表、再插入当前数，这样才能保证不会用到自己两次。
适用边界：哈希表平均 O(1)，但最坏情况（大量冲突）会退化。竞赛里常见的做法是：值域小就用桶数组（更快更稳）；需要有序（比如找前驱后继、计数第 k 小）就必须用 map/set，不能只看“快”。

4.3 离散化：值域 10⁹，但只有十几个数

问题：数组里的数是 [4, 1000000, 3, 999999999, 42, 3, 1000000] 这种，值特别大。想做“按值开桶计数”显然开不下 10⁹ 的数组。

原数组（值很大，值域约 10⁹）

离散化之后（值域压缩成 1〜k，k = 不同值的个数）

做法：把数组复制一份 → 排序 → 去重，得到 b。那么“值 x 的排名”就是 x 在 b 中的下标 + 1。用 lower_bound(b, x) 得到排名，O(log n)。
压缩之后，值域从 10⁹ 变成 k（不同的值有几个就是几），就可以放心地开桶、上树状数组了。
适用边界：离散化只保留“相对大小关系”，会丢掉原本的数值大小（比如原本差值大小）。如果题目要问“两数之差”，离散化之后必须回查原值。
另外：离散化之后再用树状数组统计，本质上是把“值域上的前缀和”变成了“排名上的前缀和”，这是逆序对/主席树类题目的标准起手式。

五、枚举点对或子区间，O(n²) 太慢 J S

暴力做法：双重循环枚举所有 (i, j) 或所有子区间 [l, r]。数量是 n(n+1)/2，n=10⁵ 时约 5×10⁹，必超时。

瓶颈：两层循环里，内层循环做的事情有很大一部分是重复或者可以推断出来的——比如窗口右移一格时，和只需要加上新元素、减掉旧元素，不必重新累加整段。
优化方向：让内层指针“只朝一个方向移动”（双指针），把“一段区间的和”变成“两个前缀相减”（前缀和 + 哈希），或者用“分治”把 n² 的统计变成 n log n，或者用“排序 + 贪心”直接免掉枚举。
算法难度适用条件（很重要）复杂度变化
双指针 / 滑动窗口JS区间满足单调性：窗口变长时，指标只增不减（如全正数的区间和）O(n²) → O(n)
前缀和 + 哈希JS统计“和为 k 的子数组个数”，对正负没有要求O(n²) → O(n)

5.1 双指针：最短的“和 ≥ target”的连续子数组

数组里全是正数（示意数据：10 个数，范围 1〜8）。要求找出最短的一段连续区间，使它的和不小于 target。

为什么两个指针都只往右走：因为数组全是正数，右指针 r 往右移，和一定变大；左指针 l 往右移，和一定变小。
所以：当和不够时，只能移动 r（加数）；当和够了时，尝试移动 l（缩窗口）并记录答案。两个指针各自最多走 n 步，总共 O(n)。
如果数组里有负数，“移动 l 和一定变小”就不成立了，双指针会失效——只能改用前缀和 + 哈希（见 5.2）。
适用边界：双指针必须找到“单调性”才成立。常见的有：全正数的区间和、排序后的两数之和、滑动窗口内的计数。找不到单调性，就别硬套。

5.2 前缀和 + 哈希：数一数有多少个子数组的和正好等于 k

数组里有正有负（示意数据：8 个数，范围 −2〜5）。要统计所有和等于 k 的连续子数组个数。注意：这里有负数，双指针不管用。

关键式子：子数组 a[l..r] 的和 = P[r+1] − P[l]。要它等于 k，就等价于 P[l] = P[r+1] − k。
所以扫到 r 的时候，只要问一句“前面出现过多少个前缀和等于 P[r+1]−k”，答案就累加上去 —— 用哈希表（或桶）记“每个前缀和出现过几次”。一次遍历，O(n)。
适用边界：①哈希的 key 是前缀和，值域可能很大（有负数），所以用哈希表而不是数组。②别忘了先初始化 map[0] = 1，否则漏掉“从下标 0 开始的子数组”。③如果值域不大（前缀和范围很小），直接用数组当桶更快。

5.3 分治（归并排序）：数逆序对，n² 变 n log n

逆序对：一对 (i, j) 满足 i < j 但 a[i] > a[j]。暴力双重循环，n(n−1)/2 次比较。

分治的想法：把数组从中间切成两半，逆序对分三种：
① 左右两半各自内部的（递归解决）；② 一个在左、一个在右的（在归并合并的过程中顺便数）。
合并时，如果右半边的元素要放在左半边的前面，说明左半边剩下的所有元素都比它大 —— 一次性加上“左边还剩几个”这么多个逆序对。
因为每个元素在每一层只参与一次比较，一共 log n 层，所以是 O(n log n)。
适用边界：逆序对也可以用树状数组 + 离散化做（把值离散化后，从右往左扫，问“已经出现过多少个比我小的”），同样 O(n log n)。两种都要会，写哪个取决于你更熟哪个。另外：逆序对数最大可达 n(n−1)/2，n=10⁵ 时约 5×10⁹，要开 long long。

5.4 排序 + 贪心：区间调度（最多能参加几个活动）

给出 10 个活动的时间段 [开始, 结束]，一个人同一时间只能参加一个活动，问最多能参加几个。暴力：枚举所有子集，检查是否两两不冲突，共 2¹⁰ 种。

（示意数据：时间轴 0〜20，10 个随机区间）
贪心的结论：把活动按结束时间从小到大排序，然后从头扫一遍，只要开始时间不早于上一个选中的结束时间，就选它。
为什么这样对？（交换论证）任何一份最优方案里，第一个活动都可以换成“结束最早的那个”，换成它之后不会让后面的活动更难安排。如此反复，贪心一定是某个最优解。
适用边界：①按结束时间排序，不是开始时间，也不是时长——按开始时间排序会给出反例；②贪心一定要能证明或至少举反例检验，写之前先在草稿纸上试几个小数据；③同一个问题换个目标函数（比如“总时长最大”而不是“活动数量最多”）贪心就不成立了，那是另一道题。

六、枚举答案的范围太大 J S

暴力做法：答案可能是 0〜10⁹ 之间的某个数，那就从 0 开始一个一个试，每个候选都花 O(check) 验证一下。总代价 = 值域 × check。

瓶颈：答案虽然很多，但很多候选“一眼就知道不行”，甚至能通过一次验证排除掉一大片。
优化方向：如果“答案越大越容易满足”（或越小越容易满足），就可以二分答案：把“求最优值”变成“判定某个值行不行”，每次排除一半。或者函数是单峰的时候用三分。有时候答案有更简单的性质，直接贪心推出来，连试都不用试。
方法难度什么时候能用复杂度变化
二分答案JS答案有单调性：出现“最大值最小”“最小值最大”“至少/最多”这类字眼O(值域 × check) → O(log 值域 × check)
三分S函数在区间上单峰（先升后降 / 先降后升）O(值域) → O(log 值域 × 单次求值)
贪心JS每一步的局部最优能推出全局最优（需要能证明）完全免掉枚举

6.1 二分答案：砍树

问题（经典题）：有若干棵树，伐木机设定高度 H，把所有比 H 高的树在 H 处锯平，锯下来的木头总长度要 ≥ m。求满足条件的最大 H。（题意：H 越大，锯下来的越少——这就是单调性。）

树高（示意数据：8 棵树，高度 0〜25）

为什么能二分：H 越大 → 锯下来的木头越少。这个关系是单调的，所以可以二分：
如果 check(H) ≥ m（够），说明 H 还可以更高 → lo = mid+1；如果不够 → hi = mid−1。
适用边界（极其重要）：①必须先确认单调性，写不出“越大越……/越小越……”就不要用二分答案；②注意二分的写法：这题求“满足条件的最大 H”，所以是 if(check(mid)) ans=mid, lo=mid+1; else hi=mid-1;；求“最小”则反过来；③check 函数本身要控制好复杂度，二分答案的总复杂度 = log(值域) × check 的复杂度；④答案的上下界要开够，不然会漏解。

6.2 三分：求单峰函数的极值

函数 f(x) = −(x−3.2)² + 10 在 x ∈ [0.5, 5.9] 上是“先升后降”的单峰函数。三分法每次把区间按 1/3、2/3 处取两个点，把不可能包含峰的那一段砍掉。

三分每一步做了什么：取两个三等分点 m1、m2。如果 f(m1) < f(m2)，说明峰在 m1 右边 → 丢掉左边 1/3；反之丢掉右边 1/3。每轮区间缩到原来的 2/3。
适用边界：①三分要求函数在区间上严格单峰（不能有平台、不能多峰），否则结论不成立；②每轮要算 2 次函数值，比二分“贵”；③竞赛里三分出现频率远低于二分答案，知道思路即可。

6.3 贪心：直接免掉枚举

以经典的“排队接水”为例：n 个人接水，每人有接水时间 tᵢ，求怎样安排顺序，使所有人的等待时间总和最小。
暴力：枚举所有排列 n! 种，每种算一遍总和。贪心：把人按接水时间从小到大排序即可。

为什么排序最优：接水快的人排前面，他的时间会被后面每个人“等待”一次——把短时间放在前面，短时间的“重复次数”就多，总等待时间自然更小。
这类题在 J 组非常常见（排队接水、国王游戏、区间调度），套路是：先想清楚“交换相邻两个元素会怎样”，再决定按什么排序。
适用边界：贪心不是万能的。“按什么排序”必须通过交换论证或反例检验确认。写之前一定在草稿纸上试 3～4 个元素的手算反例，确认排序关键字选对了。

七、搜索指数级爆炸 J S

暴力做法：纯 DFS/回溯，把所有分支都走一遍。分支数是指数级的（2ⁿ、n!、nⁿ），n 一过 20 就彻底走不动了。

瓶颈：走了大量注定失败的分支；或者同一个状态被不同的路径重复到达，反复搜索。
优化方向：①剪枝——提前判断这条分支不可能出解，直接返回；②BFS——求“最少步数”时，只记每个状态第一次被访问的距离，不重复走；③记忆化——同一个状态只搜一次；④状压 / 位运算——把集合压缩成一个整数，转移变 O(1)；⑤折半搜索——把指数拆成两半。

7.1 剪枝：N 皇后，从 1900 万次到 2000 次

问题：在 n×n 的棋盘上放 n 个皇后，互相不能攻击（不能同一行、同一列、同一斜线）。统计方案数。

剪枝 DFS 找到的第一个解（n = ）

暴力是怎么做的：一行一行放，每行有 n 种位置，全部放完（n 行都放好）之后才检查有没有冲突。节点数 = 1 + n + n² + … + nⁿ。
剪枝怎么做的：每放一个皇后，立刻用位掩码判断这一列、这两条斜线有没有被占——冲突就 return，不再往下试。
表格里的“剪枝 DFS 访问节点”是真的跑了一遍数出来的。
适用边界：①剪枝能优化多少，完全取决于“能否尽早判定失败”，所以要先写最狠的可行性剪枝（比如位运算），再考虑顺序上的优化（优先试约束最紧的选择）；②最优性剪枝需要先有一个“还不错”的初始解（贪心求一个），否则剪不掉多少；③剪枝的复杂度无法用大 O 表达，只能靠实测和估算。

7.2 BFS：为什么求“最少步数”不能用 DFS 枚举所有路径

迷宫（示意数据：9×9，深色格是墙）。要从 S 走到 G，最少走几步？S = 起点，G = 终点。

BFS 的重点：一层一层往外扩。第一次访问到某个格子时，走的就是最短距离——所以每个格子只需要访问一次。
暴力做法（DFS 枚举所有路径）会走遍所有可能的走法，路径数是指数级的；BFS 只访问每个格子一次，复杂度是 O(格子数)。
适用边界：①BFS 求“最短步数”的前提是每步代价相同（边权为 1）。如果边权不同，必须用 Dijkstra（见 8.1）；②迷宫状态数一般不大，但像八数码这种状态空间大、要用哈希表/康托展开去重的题，BFS 必须配合状态压缩；③队列要开够大，C++ 里常用 queue + vis 数组。

7.3 折半搜索：n = 40 也能过

问题：n 个物品，每个选或不选（或者正负号），问有多少种取法满足某个条件。暴力 2ⁿ；n = 40 时 2⁴⁰ ≈ 1.1×10¹²，不可能跑完。

做法：把 n 个物品切成两半（各约 n/2 个），分别枚举两半的所有 2^(n/2) 种情况，把结果存进数组；对其中一半排序；然后枚举另一半的每种情况，去前半段里二分查找能和它配对的答案。
总额外代价：排序 2^(n/2) 个元素，O(2^(n/2) · n/2)。
适用边界：①折半搜索要求“两半的结果可以合并”（可加、可配对）；②n 超过 44 左右就撑不住了（2²²=4M 已经是内存和时间的极限）；③如果题目里 n 很小但值域很大，用 meet-in-the-middle；如果 n 大但值域小，用 DP（01 背包）。选择依据是“哪一维小就对哪一维做指数”。

八、图论中的重复遍历 J S

暴力做法：枚举所有路径找最短路、对每对点都跑一次最短路、判断连通性时反复 DFS、求有依赖关系的顺序时反复尝试……全是重复劳动。

瓶颈：同一个点、同一条边被反复访问；某些信息（比如“这两个点是不是连通”）算过一次之后从来没被记住。
优化方向：用“只处理一次”的算法替换“反复枚举”——最短路（Dijkstra/Floyd/BFS）、并查集（连通性）、拓扑排序（依赖顺序）、倍增 LCA（祖先）、Tarjan（强连通分量/割点/桥）。

8.1 Dijkstra：每个点只“定型”一次

示意图（6 个点、9 条带权边，边权 = 走路时间）。从 0 号点出发，单步播放看距离数组是怎么被更新的。

三步循环：①在所有还没定型的点里，挑距离最小的那个 u（定型，以后不再改）；②检查 u 的每一条出边 (u,v,w)，如果 dist[u]+w < dist[v]，就更新 dist[v]（这一步叫“松弛”）；③重复。
因为每次都挑最小的，所以“定型后不会再被改小”——这是 Dijkstra 正确性的关键。挑最小的动作刚好可以用堆（第 3.3 节）来加速。
适用边界：Dijkstra 不能处理负权边！有负权要用 SPFA（或 Bellman-Ford）。另外：把所有点初始 dist 设为 0 丢进队列，第一次跑完就是“多源最短路”；只求一点到另一点时，找到终点就可以提前 break。

8.2 并查集：判断连通，近似 O(1)

问题：一开始 8 个点各自独立，做若干次“合并两个集合”和“查询两个点是否连通”。暴力做法：每次查询就 DFS 一遍，O(n+m)。并查集用一棵“代表元树”来表示集合。

拖到 0 = 关闭压缩，1 = 开启压缩，观察 parent 数组和 find 步数的变化
find(x)：一路往上找，直到找到“自己是自己父亲”的那个点（叫根 / 代表元）。两个点的根相同 ⇒ 连通。
路径压缩：找到根之后，顺手把路径上所有点的父亲直接改成根。这样下次再查同一个点，一步就到。
按秩合并（这里没演示）：合并时把“矮树”挂到“高树”下面，避免树变长。两者结合后，单次操作的平均代价近似 O(α(n))，可以当成 O(1)。
适用边界：并查集只支持合并，不支持删除/分裂（要支持得用可撤销并查集按时间分治）。另外：并查集只能回答“连通不连通”，回答不了“经过哪些点”“怎么走”——那需要真的存图。

8.3 Floyd 还是“n 次 Dijkstra”？看数据规模选

如果要求“任意两点之间的最短路”，有两种思路：①Floyd：三重循环，O(n³)；②从每个点出发跑一次 Dijkstra（堆优化），总 O(n(m log n))。

稀疏图（边数 ≈ 4n）用 n 次 Dijkstra 更好；稠密图（边数接近 n²）时 Dijkstra 的 log 因子反而不划算，Floyd 更简单直接，而且常数小、代码短（5 行）。
所以比赛里常见判断：n ≤ 500 就用 Floyd（好写、不易错）；n 大且图稀疏就用 Dijkstra。
适用边界：Floyd 允许负权边（只要没有负环），Dijkstra 不行。Floyd 还可以顺便判断负环（跑完之后 dist[i][i] < 0 就有负环）。

8.4 倍增 LCA：一步一步往上爬 vs 跳着爬

示意树（18 个点，是一条长链 + 两个分支，最深 16 层）。问两个点的最近公共祖先（LCA）。拖动选择两个点。

暴力：先把深的那个点一步一步往上挪，直到和另一个一样深；然后两个一起一步一步往上挪，直到相遇。步数 = 深度差 + 2 × 层数差。
倍增：预处理 up[k][i] = “从 i 往上跳 2ᵏ 步到达的点”。然后从大往小尝试跳跃（先试跳 8 步、再 4 步、2 步、1 步），一次就能跨过很大一段。步数约 2 log n。
适用边界：①倍增要求树是静态的（不动态改结构）；②预处理 O(n log n) 时间和空间，n = 10⁵ 时 up 表约 17×10⁵ 个 int，够用；③倍增思想还用于“倍增找第 k 个祖先”“倍增求区间最值（就是 ST 表）”“倍增跳表”。

九、数论与数学 J S

暴力做法：判断质数就从 2 一直试到 n−1；算 aᵇ 就连乘 b 次；求 gcd 就一个一个数去试；求一堆组合数就每次重新算。

瓶颈：数论题的暴力是“把整个值域都走一遍”，而正确答案往往只需要考虑很少一部分（√n 以内的因子、b 的二进制位、筛出来的质数表）。
优化方向：把“一次性预处理”的结论反复使用——筛法建质数表、预处理阶乘和逆元、预处理欧拉函数。
暴力优化难度复杂度
判断质数：试除到 n试除到 √n（若 n = a×b，必有一个 ≤ √n）JO(n) → O(√n)
求 1〜n 所有质数：逐个判断埃氏筛 / 线性筛JSO(n log log n) / O(n)
算 aᵇ mod p：连乘 b 次快速幂（二进制拆分指数）JSO(b) → O(log b)
求 gcd：枚举 1〜min(a,b)辗转相除（欧几里得）JO(n) → O(log n)
反复算组合数 C(n,m)预处理阶乘 + 逆元S每次 O(n) → O(1)
解 ax+by=c / 求逆元扩展欧几里得 / 费马小定理SO(log n)
常见坑：①判断质数时 i*i <= n 比 i <= sqrt(n) 更安全（避免浮点误差），但 i*i 可能溢出 int，n 大时写成 i <= n/i；②筛法数组开到 n+1；③快速幂里底数要先取模，乘法要用 long long 防止溢出；④组合数的逆元需要模数是质数（费马小定理），模数不是质数就得用 exgcd。

9.1 判断质数：试除到 √n

关键结论：如果 n 不是质数，一定能写成 n = a × b（a ≤ b），那么 a ≤ √n。所以只要试除到 √n 就能判断，不用试到 n。

（位太多时用实际次数估算，不会真的跑几百万次循环）
次数对比：试除到 n 是 n−2 次；试除到 √n 是 ⌊√n⌋−1 次。n = 10⁹ 时，前者约 10⁹ 次（必超时），后者只要约 31623 次。
边界：①n = 1 和 n = 0 特殊处理（1 不是质数）；②偶数可以先判一下（除 2 之后只试奇数，次数再少一半）；③如果要判断很多个数是不是质数，别一个个试除，直接先筛出 √Max 里的质数，用质数去试除更快。

9.2 埃氏筛：一次预处理，之后 O(1) 查质数

问题：统计 1〜n 里有多少个质数，或者要多次问“x 是不是质数”。逐个试除的总代价是 Σ√i ≈ n√n 级别；埃氏筛一次扫完，O(n log log n)。

做法：从小到大看每个数 i，如果 i 还没被标记过，说明 i 是质数；然后把它所有 ≥ i² 的倍数全部标记成合数。
为什么从 i² 开始标：i × 2、i × 3 … i × (i−1) 这些数已经在小质数（2、3、…、i−1）的时候被标过了，重复标浪费时间。
边界：①数组要开到 n+1，标记时从 i×i 开始，注意 i×i 别溢出；②复杂度真实值是 O(n log log n)，非常接近线性；③要线性复杂度（每个合数只被标记一次）用线性筛（欧拉筛），同时能顺便求出每个数的最小质因子，是积性函数筛法的模板；④如果 n 只有 10⁶ 以内，埃氏筛完全够用。

9.3 快速幂：把 b 次乘法变成 log b 次

要算 aᵇ mod p。朴素做法乘 b 次。快速幂看的是b 的二进制展开：b 的每一个 1 位对应一次乘法，剩下用“平方”推进。

算法（边算边看）：res = 1；只要 b 还大于 0：
① 如果 b 的最低位是 1，就 res = res × a % p（用上这一位）；
② a = a × a % p（底数平方，准备给下一位用）；③ b >>= 1（指数右移一位）。
乘法次数 = ⌊log₂b⌋（平方次数）+ popcount(b)（1 的个数）。
边界：①底数先取模；②res × a 在 p 接近 10⁹ 时会超过 int，必须用 long long；③如果要算 aᵇ mod p 而 p 很大（> 2⁶³），要用“快速乘”或 __int128；④指数 b 也经常是 10¹⁸ 级别的，用 long long 读入，算法本身照样是 log 级。

9.4 辗转相除：gcd 只要一行

求两个数的最大公约数。暴力：从 1 试到 min(a,b)，或者从 min(a,b) 往下试。辗转相除：gcd(a,b) = gcd(b, a mod b)，直到 b = 0。

（8 组预设数据，都是常见例题里的数）
为什么快：每做一次取模，较大的那个数至少缩小一半（斐波那契数列是它最坏的情况），所以步数是 O(log min(a,b))，通常十几次就结束。
可以直接用：C++17 起有 std::gcd；__gcd 在部分环境可用；自己写也就一行 return b ? gcd(b, a%b) : a;。
边界：①做取模前注意 a、b 是否为 0（gcd(x,0)=x）；②递归层数是 log 级，不用担心栈溢出；③扩展欧几里得（exgcd）在这一行里多维护两个系数，用来解 ax+by=gcd(a,b)，是求逆元、解不定方程的通用工具。

十、字符串 J S

暴力做法：在主串里对每一个可能的起点，逐字符和模式串比较。最坏情况 O(n·m)。

瓶颈：一次失配之后，暴力做法把主串指针也退回去重来，前面已经比较过的字符又比了一遍。所以一旦模式和主串有很多重复字符，就会反复比较同一段。
优化方向：KMP 让主串指针永不后退（用模式串自己算出的 π 数组决定跳到哪里）；字符串哈希把“比较两段字符串”变成“比较两个整数”；Trie 把“多个串的公共前缀”只存一次；AC 自动机把 Trie 和多模式匹配结合起来。

10.1 KMP：失配之后，指针不回退

选一组数据，看看暴力匹配和 KMP 各自比较了多少次字符。三组数据里有一组是“最坏情况”，专门用来暴露暴力的弱点。

模式串的 π 数组（前缀函数）：π[i] = 前 i+1 个字符里，最长的“既是前缀又是后缀”的长度

KMP 在干什么：比较到第 j 个字符失配时，说明前 j 个字符已经匹配成功了。既然它们匹配成功，那么“这 j 个字符的后缀”和“模式串的前缀”中相同的部分，就不需要重新比了——π[j−1] 就是那个长度。所以让 j = π[j−1]，主串指针原地不动继续比。
总比较次数：因为主串指针不后退、模式指针回退总量不超过前进总量，所以是 O(n+m)。
常见坑：①π 数组的下标含义有两种写法（π[i] 表示长度为 i 的前缀，或者表示以 i 结尾的前缀），换模板时一定要对着题目重推一遍；②求 π 的时候用的是“模式串和它自己匹配”，代码结构和主匹配几乎一样；③KMP 只找“某个模式串”，如果要多个模式串一起匹配（比如关键词过滤），要用 AC 自动机。

10.2 字符串哈希：O(1) 判断两段子串是否相同

字符串 s = "abcabcabca"（10 个字符）。拖动选择两段子串，看看“逐字符比较”和“哈希比较”的代价差多少。

做法：把字符串看成一个 base 进制的大数，预处理前缀哈希 h[i]（前 i 个字符的哈希值）和 base 的幂次表 pow[i]。
那么子串 [l, l+len) 的哈希 = (h[l+len] − h[l] × pow[len]) mod M，只要 O(1) 乘减。
这里为了演示用了 M = 1000000007、base = 131（实际比赛里常用双哈希或者自然溢出，降低冲突概率）。
边界：①哈希是概率算法——不同的子串理论上可能撞到同一个值（冲突）。比赛里常用“双哈希”（两个不同模数）或大模数把概率压到可忽略；②被卡哈希的题是存在的（出题人故意构造冲突），重要比赛建议用双哈希 + 随机 base；③比较两个子串是否相等也能用后缀数组 LCP，但哈希更短更通用。

10.3 Trie（字典树）：公共前缀只存一次

把几个单词插进 Trie，然后看查询 / 前缀匹配的代价。示意数据：5 个单词。

为什么快：所有单词的公共前缀在 Trie 里只存一份（比如 app、apple、apply 的 "app"），所以查找某个单词只需要走“单词长度”步，和“一共有多少个单词”“单词有多长”都无关。
暴力做法是“把所有单词都看一遍，逐个比较”——代价是所有单词长度之和。
适用边界：①Trie 的空间 = 所有单词的总长度 × 字符集大小（用数组存孩子时），单词很多时内存可能爆，可以用 map 存孩子或者用 0/1 Trie 压缩；②Trie 天然支持“前缀查询”“字典序第 k 小”“最大异或对（01 Trie）”；③多模式串匹配要在 Trie 上加失配指针，那就是 AC 自动机。

十一、树上操作 S

暴力做法：对树上一条路径上的所有点加点值，就沿着路径一个点一个点爬；问子树信息，就把子树里的点全部遍历一遍。

瓶颈：树上的“路径”和“子树”在数组里并不连续，所以没法直接用数组的区间操作（前缀和、树状数组、线段树）。
优化方向：把树“压扁成数组”——用 DFS 序让每棵子树对应一段连续区间；用树上差分把路径修改变成几个点上的 O(1) 修改；用树链剖分把路径也切成若干段连续区间。

11.1 DFS 序：把子树变成一段连续区间

示意图（8 个点）。按 DFS 顺序给每个点标上进入时间 tin 和离开时间 tout，单步播放看这个过程。

核心结论：以点 u 为根的整个子树，在 DFS 序数组里正好占据连续的一段 [tin[u], tout[u]]。
所以“给子树里所有点加 v”就变成“给数组的 [tin[u], tout[u]] 区间加 v”——树状数组、线段树全都能用了。
怎么快速判断 v 是不是 u 的子孙：tin[u] ≤ tin[v] ≤ tout[u]。
边界：①DFS 序要求树是静态的（不能中途改结构）；②如果还需要“路径”上的操作（不只是一整棵子树），光有 DFS 序不够，要用 树链剖分（把路径拆成 log n 段连续区间）或树上差分；③当心递归深度——n = 10⁵ 的一条链会让递归爆栈，要写迭代版或者手动开大栈。

11.2 树上差分：路径加值，4 次修改搞定

问题：给树上从 u 到 v 的路径上每个点加 1，做很多次之后问每个点的最终值。（示范用同一棵 8 个点的树）

要点差分的 4 笔操作：设 w = LCA(u, v)，p = w 的父亲，那么
cnt[u] += 1  cnt[v] += 1  cnt[w] −= 1  cnt[p] −= 1
然后从根做一次 DFS，把 cnt[父] += cnt[子] 累加上去，得到的就是每个点被经过的次数。
（如果题目要求“边”被经过的次数，写法稍有不同：cnt[u]+=1, cnt[v]+=1, cnt[w]-=2。）
适用边界：树上差分适合“多次修改、最后统一查询”。如果要求“每次修改后立刻能回答某个点的值”，那要上树链剖分 + 线段树（O(log²n)）或者用 LCA + 树状数组。

11.3 树的直径：两次 DFS

直径 = 树上最远两点之间的距离。结论：从任意点出发找到最远的点 A，再从 A 出发找到最远的点 B，那么 A→B 就是一条直径。

为什么两次就够（直观理解）：第一次 DFS 找到的 A 一定是“某条直径的一个端点”（证明用反证法：如果 A 不是任何直径的端点，可以构造出更长的路径）。所以第二次从 A 出发的最远点 B，就一定和 A 组成直径。
跑两次 DFS 是 O(n)，比“枚举两个点再求距离”的 O(n²) 或 O(n² log n) 快得多。
边界：①这个“两次 DFS”的结论对边权非负的树成立。如果边权可能为负，必须用树形 DP；②树的重心（删掉它后最大连通块最小）也是用一次 DFS 求子树大小就能算出来；③直径常和“树上最远点对”“树的中心”一起考。

十二、多次询问可以离线 S

暴力做法：按题目给的顺序，一个一个询问去算，每次都要重新扫一遍数据。

瓶颈：询问的顺序是题目给定的，但这个顺序对计算并不友好。相邻两次询问的区间可能离得很远，导致指针/区间反复来回移动。
优化方向：反正答案最后一起输出——那就把询问重新排序，让相邻两次询问尽量“挨着”。这就是离线：先收下所有询问，重新安排处理顺序，再统一回答。
技术思路难度复杂度
离线排序把询问按某个维度（左端点 / 右端点 / 值）排序，用双指针或树状数组一次扫完SO((n+q) log n)
莫队把询问按“块”排序，使区间端点总移动量降到 O(n√q)S偏难O(n√q × 单次增删代价)
整体二分对答案二分，把所有询问一起丢进去分治NOI 向按题目而定

12.1 莫队：把“指针乱跑”变成“按块有序移动”

场景：n = 100 的数组，有 q 个区间询问，每个询问的答案可以通过“在区间两端增删一个元素”O(1) 更新（比如区间内不同数的个数）。
把询问按左端点所在的块排序（同一块内再按右端点排序，奇数块降序偶数块升序），就能让左右两个指针的总移动量大幅下降。

为什么块大小是 n/√q：左指针在块内乱跳，块的宽度是 B，跳 q 次 → 总代价 q·B；右指针在每个块内单调移动，共有 n/B 个块，每块最多走 n → 总代价 n²/B。
两者相加 q·B + n²/B，在 B = n/√q 时取最小。这就是“块大小取 n/√q”的由来，也是 O(n√q) 的来源。
适用边界：①莫队要求“答案能通过 O(1) 增删区间端点来更新”，比如计数类问题（不同数个数、区间众数近似、区间出现次数）；②区间求和这类问题不需要莫队，直接前缀和更快；③修改类问题要用“带修改莫队”（多一维时间 + 块大小取 n^(2/3)，复杂度 O(n^(5/3))）；④莫队常数大，nq 相同时优先考虑别的做法。

12.2 离线排序 + 树状数组：区间内有多少个不同的数

问题（经典）：数组里有重复元素，多次询问“区间 [l, r] 里有多少个不同的数”。
在线做很难（没法用前缀和相减）。离线做法：把所有询问按右端点 r 从小到大排序，然后用一个指针从前往后扫数组，同时用树状数组维护“每个值最后一次出现的位置为 1，其他为 0”。

示意数据：15 个数（取值范围 1〜5，故意有很多重复），4 个询问，已按右端点排好序
核心技巧：“一个值在区间里出现多次，只算一次”——那么对每个值，我们只关心它最后一次出现的位置。
当扫到位置 i、值是 v 时：如果 v 之前出现过（位置 j），就把树状数组上位置 j 减 1；位置 i 加 1。这样任何时刻，树状数组上“1 的位置”就是每个值最后一次出现的位置。
那么询问 [l, r]（此时扫到 r）的答案 = “位置 ≥ l 且 ≤ r 的 1 的个数” = 树状数组上 (r 的前缀和) − (l−1 的前缀和)。
适用边界：①必须是离线（先把询问全读进来）——因为答案要依赖排序后的处理顺序；②强制在线（每条询问必须立刻回答）就用不了，那要用主席树/可持久化；③同样的套路可以解决“区间内 ≥ k 的数的个数”“区间内只出现一次的数”等一系列问题，关键是找到“按什么排序 + 用什么维护”。

十三、J 组的其他「优化」 J

这一节不是算法，而是让暴力“能跑起来”的底层技巧。J 组里它们出现的频率极高。

技巧解决什么要点
高精度数超出 long long / int 的表示范围用数组（或字符串）逐位模拟加、减、乘。这不是优化，而是突破表示范围。
滚动数组DP 数组太大，内存爆掉当 dp[i] 只依赖 dp[i−1] 时，把 n 行压成 2 行甚至 1 行。

13.1 高精度：long long 装不下的数怎么算

用数组（每个格子存一位）模拟竖式加法。拖动位数，看看什么时候开始“装不下”。

模拟竖式：从最低位开始，两数对应位相加再加进位，当前位 = 和 % 10，进位 = 和 / 10。数组一定要开够（比如两数最多 500 位，就开到 505）。
边界与坑：①最高位是否要进位要单独判断（长度可能 +1）；②读入时通常是字符串，最低位在下标 0 还是最高位在下标 0 要统一好，别搞混；③高精度乘法、除法更复杂（除法是“试商”，要用减法模拟），先熟练掌握加法减法再写乘除；④能用 __int128 或 Python 就别写高精度。

13.2 滚动数组：把 n×V 的 DP 表压成一行

0/1 背包的 DP 表是 n 行 × (V+1) 列。但如果发现“算第 i 行时只用到第 i−1 行”，就可以只留两行（甚至一行）——空间从 O(nV) 变成 O(V)。

为什么能省：填第 i 行时只读第 i−1 行的数据，再往前的行再也不会被用到，留着就是浪费内存。
进一步（原地滚动 / 一维数组）：01 背包的容量要从 V 倒序枚举到 w[i]，这样 dp[j] 用的是“上一轮”的 dp[j−w[i]]；如果正序枚举，就变成完全背包了。这是背包九讲里最经典的细节。
适用边界：①只有当“本层只依赖上一层”时才能滚动——如果 DP 需要访问更早的行（比如区间 DP、状压 DP 的某些写法），就不能滚；②如果题目要输出方案（具体选了哪些物品），滚动会丢掉中间状态，必须保留完整表格或用额外数组记录决策。

最后：三个自问清单

写题时按顺序问自己三句话：
① 暴力是什么？写出来，写清楚它的复杂度（数一数最内层语句执行多少次）。
② 它到底在重复什么？重复算状态 → DP；重复扫区间 → 前缀和/双指针；重复找最值 → 堆/单调队列；重复查值 → 哈希/二分；重复走路径 → BFS/最短路。
③ 数据范围告诉了我什么？n ≤ 20 → 指数级算法能过；n ≤ 500 → O(n³) 能过；n ≤ 5000 → O(n²) 能过；n ≤ 10⁵ → 要 O(n log n)；n ≤ 10⁶ → 要接近 O(n)。数据范围永远是最诚实的提示。
真正掌握的标志：看到一个暴力，能立刻说出“这里重复了什么，可以用什么把它存下来或排除掉”——而不是背下了多少种算法。
